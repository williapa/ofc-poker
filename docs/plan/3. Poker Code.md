# Prompt 3 - Poker code

Build cards, deck, and poker-hand evaluation.

## Goal

Implement the pure card primitives and conventional poker evaluator inside `game-engine`. Establish canonical card identity, parsing/serialization, deterministic deck creation/shuffling, three-card front-row evaluation, five-card evaluation, comparison keys, and tie behavior. This evaluator is foundational and must be independently trustworthy before OFC rules are layered on it.

## Acceptance criteria

- A standard deck contains exactly 52 unique cards with no jokers.
- Shuffling accepts an injected random source or deterministic deck order for repeatable tests.
- Five-card evaluation handles high card through royal flush, including ace-low straights, kickers, and exact ties.
- Three-card evaluation recognizes only high card, pair, and three of a kind; straights and flushes have no special front-row rank.
- Suits never break ties.
- Evaluation results are immutable, serializable, and suitable for row legality comparison.
- Table-driven tests cover every hand class, important kicker cases, wheel straights, royal-flush identification, and equal hands.
- Package lint, type-check, tests, and build pass.
