# Prompt 6 - Harden and document the game engine

## Goal

Perform a focused engine-quality pass before consumers are built. Add invariant/property-based testing where useful, public API documentation, snapshot migration/version handling, and multi-hand match state including cumulative score and dealer rotation. Keep policy choices explicit and configurable only where the rules reference identifies ambiguity.

## Acceptance criteria

- Tests generate or exercise many valid decks/placements and prove no duplicate cards, valid capacities, deterministic replay, and zero-sum scoring.
- Replaying the same event log yields the same state and resolution.
- Multi-hand matches preserve cumulative scores and correctly rotate the dealer and Fantasyland status.
- Unsupported snapshot/event versions fail with typed, actionable errors.
- Public engine APIs are documented with examples and do not expose mutable internal collections.
- Engine coverage is measured, meaningful uncovered branches are addressed, and no skipped/focused tests remain.
- The package passes lint, type-check, tests, and build independently.
