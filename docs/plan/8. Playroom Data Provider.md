# Prompt 8 - Playroom Data Provider

Implement and contract-test the Playroom provider

## Goal

Integrate Playroom Kit behind the provider contract. Verify the current installed SDK API while implementing rather than leaking SDK concepts into the rest of the application. Use host-authoritative action validation and state publication, safe lifecycle cleanup, and shareable lobby identifiers/links.

## Acceptance criteria

- Playroom imports exist only inside the Playroom adapter (and its tests/configuration).
- Creating and joining a room requires no application account and supports a display name.
- Only the authoritative host advances engine state; peers submit action requests and receive authoritative updates.
- Sender/seat identity is derived from trusted provider identity rather than arbitrary action payload fields.
- Duplicate, stale, malformed, unauthorized, and out-of-turn actions cannot alter authoritative state.
- Reconnect and late join restore the latest authoritative snapshot; host change follows the documented policy.
- Adapter cleanup removes listeners and avoids repeated initialization during client rerenders.
- Reusable provider contract tests pass with a mocked/fake Playroom boundary, and any manual sandbox test steps are documented.
- No secret is embedded in client code or committed files.
